## 🎤 Câu hỏi phỏng vấn thường gặp & Cách trả lời

### 1. "Bạn có thể giải thích về kiến trúc microservices trong dự án không?"

**Trả lời:**
```
"Trong dự án chat-apps, tôi thiết kế kiến trúc microservices với 8 services độc lập:

1. Infrastructure Layer:
   - Discovery Server (Eureka) cho service registration
   - API Gateway để route requests
   
2. Business Services:
   - User Service: Quản lý users và authentication
   - Chat Service: Xử lý messages (Cassandra)
   - Channel Service: Quản lý channels/groups
   - Media Service: Upload/download files (Cloudinary)
   - Notification Service: Real-time notifications (WebSocket)
   - Friendship Service: Quản lý quan hệ bạn bè

Mỗi service có database riêng (database per service pattern), giao tiếp 
qua REST API và Kafka để đảm bảo loose coupling. Tôi sử dụng Spring Cloud 
Gateway cho routing và Netflix Eureka cho service discovery."
```

### 2. "Bạn làm thế nào để implement CI/CD pipeline?"

**Trả lời:**
```
"Tôi xây dựng CI/CD pipeline với Jenkins bao gồm các stages:

1. Build Stage: Build 8 services song song bằng Maven
2. Test Stage: Chạy unit tests và integration tests
3. Docker Stage: Build Docker images cho mỗi service
4. Push Stage: Push images lên Docker Hub
5. Deploy Stage: 
   - Dev: Auto-deploy khi commit vào develop branch
   - Staging: Auto-deploy với comprehensive testing
   - Production: Require manual approval, backup DB trước khi deploy

Pipeline được viết bằng Jenkinsfile (Pipeline as Code), version controlled
cùng với code. Tôi cũng setup GitHub webhook để trigger build tự động khi
có push."
```

### 3. "Làm sao để đảm bảo security cho ứng dụng?"

**Trả lời:**
```
"Tôi implement nhiều security layers:

1. Authentication & Authorization:
   - Tích hợp Keycloak với OAuth 2.0 và OpenID Connect
   - JWT tokens cho stateless authentication
   - Role-based access control (RBAC)

2. Network Security:
   - Tất cả services trong private Docker network
   - Chỉ expose API Gateway ra ngoài
   - Firewall rules và rate limiting

3. Data Security:
   - Encrypt sensitive data trong database
   - HTTPS/TLS cho communication
   - Never hardcode secrets, dùng environment variables

4. Monitoring:
   - Audit logs để track user actions
   - Alert khi có suspicious activities"
```

### 4. "Bạn xử lý như thế nào khi có service down?"

**Trả lời:**
```
"Tôi implement fault tolerance strategy:

1. Health Checks:
   - Spring Boot Actuator health endpoints
   - Docker health checks với retry logic
   - Prometheus monitoring với alerting

2. Circuit Breaker:
   - Sử dụng Resilience4j
   - Fallback mechanisms
   - Graceful degradation

3. Monitoring:
   - ELK Stack cho centralized logging
   - Prometheus + Grafana cho real-time monitoring
   - Alert qua email/Slack khi có issues

4. Recovery:
   - Auto-restart với Docker restart policies
   - Backup và restore procedures
   - Rollback capability trong CI/CD pipeline"
```

### 5. "Bạn scale ứng dụng như thế nào khi có nhiều users?"

**Trả lời:**
```
"Kiến trúc microservices cho phép scale linh hoạt:

1. Horizontal Scaling:
   - Chạy nhiều instances của service nào cần
   - Load balancing tự động với Eureka và Gateway
   - Stateless services để dễ scale

2. Database Optimization:
   - Database indexing cho queries
   - Cassandra cho distributed data storage
   - Connection pooling

3. Caching:
   - Redis cho session và frequently accessed data
   - CDN cho static assets

4. Async Processing:
   - Kafka cho long-running tasks
   - WebSocket cho real-time updates
   - Event-driven architecture để decouple services

5. Container Orchestration:
   - Docker Compose cho development
   - Kubernetes cho production (ready to deploy)"
```
